\section{CA-2 --- Falha sem documento}

Basta submeter um evento cuja família prevista seja \cd{ventoinha},
\cd{eccentric\_rotor} ou \cd{falta\_fase}. A resposta traz
\cd{documented=false}, \cd{prescription=null} e o campo \cd{suggestion}
preenchido --- e nenhuma chamada ao serviço de linguagem é feita.

\begin{lstlisting}[language=bash, caption={Verificação por linha de comando}, label={lst:ca2}]
curl -s -X POST http://localhost:8000/api/v1/diagnose \
     -H 'Content-Type: application/json' -d @evento-ventoinha.json \
  | jq '{fault: .predicted_fault, documented, prescription, suggestion}'
\end{lstlisting}

\section{CA-3 --- Cobertura após cadastro}

\begin{lstlisting}[language=bash, caption={Ciclo completo: lacuna, cadastro e nova cobertura}, label={lst:ca3}]
# 1. Antes: a familia nao esta coberta
curl -s http://localhost:8000/api/v1/health | jq '.documented_families'

# 2. Cadastrar o procedimento
curl -X POST http://localhost:8000/api/v1/documents \
  -F 'file=@procedimento-ventoinha.pdf' \
  -F 'title=Procedimento para Correcao de Falhas em Ventoinhas' \
  -F 'families=ventoinha'

# 3. Depois: a familia aparece na cobertura
curl -s http://localhost:8000/api/v1/health | jq '.documented_families'

# 4. O mesmo evento agora recebe prescricao
curl -s -X POST http://localhost:8000/api/v1/diagnose \
     -H 'Content-Type: application/json' -d @evento-ventoinha.json \
  | jq '.documented, .prescription.citations'
\end{lstlisting}
