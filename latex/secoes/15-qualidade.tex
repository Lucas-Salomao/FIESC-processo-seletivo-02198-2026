\begin{decisao}
O cliente de linguagem foi definido como \textbf{protocolo} (interface
estrutural), não como classe concreta a herdar. A consequência: o \textit{fake}
não precisa importar nem conhecer a implementação real --- basta ter os três
métodos com as assinaturas corretas. Isso mantém o código de teste livre de
dependência sobre a biblioteca de nuvem, que assim não precisa nem estar
instalada para a suíte rodar.
\end{decisao}

\subsection{O teste mais importante da suíte}

\begin{lstlisting}[language=Python, caption={O teste que verifica a garantia central: o modelo não é chamado para família sem documento}, label={lst:testeguard}]
def test_undocumented_never_calls_llm(fake_llm, undocumented_family, event):
    """Familia sem chunk indexado nao deve produzir NENHUMA chamada ao modelo."""
    fake_llm.generate_calls.clear()

    prescription, suggestion = rag_service.prescribe(
        undocumented_family, event, fake_llm
    )

    assert prescription is None            # nao ha prescricao
    assert suggestion is not None          # ha aviso e sugestao de registro
    assert fake_llm.generate_calls == []   # <- a garantia: zero chamadas
\end{lstlisting}

A última asserção é o que distingue uma garantia de uma intenção. Sem ela, uma
refatoração futura poderia mover a verificação de cobertura para \emph{depois}
da montagem do \textit{prompt} --- o comportamento visível continuaria correto,
mas o modelo passaria a ser chamado, e o custo e o risco de alucinação
voltariam sem que ninguém percebesse.

\begin{nota}
As credenciais de nuvem existem apenas como segredos de repositório e como
arquivo local não versionado. O fluxo de CI \textbf{não} as recebe, porque não
precisa: o \textit{fake} implementa a mesma interface do cliente real e é
injetado por sobrescrita de dependência. Um fluxo de CI que exige segredos para
rodar é um fluxo que ninguém consegue executar em um \textit{fork}.
\end{nota}

\section{Lacunas conhecidas de teste}

\begin{limitacao}
\begin{itemize}
  \item \textbf{O \textit{worker} MQTT não tem teste automatizado.} Sua
    verificação é o roteiro manual da Seção~\ref{sec:demonstracao}. A ausência é
    consciente: um teste real exigiria \textit{broker} embarcado no fluxo de CI.
    A lógica testável --- validação e canonicalização --- é compartilhada com a
    API e está coberta por lá.
  \item \textbf{A interface não tem teste automatizado.} É camada de
    apresentação sem lógica de domínio; o risco de regressão silenciosa é baixo
    e o custo de instrumentação seria alto.
  \item \textbf{Os testes de analítica são pulados sem PostgreSQL.} Eles exigem
    recursos estatísticos ausentes no SQLite. São executados no fluxo de CI, que
    provê o banco como serviço.
  \item \textbf{Não há teste de carga.} Os números de latência citados neste
    documento vêm de medição pontual em ambiente local, não de teste de
    desempenho sistemático.
\end{itemize}
\end{limitacao}
